# Architecture Decision Record (ADR) 0007: 안전한 콜드 스타트 테스트 부트스트랩

* **상태:** 채택됨 (Accepted)
* **일자:** 2026-09-12
* **결정자:** Isthis & Codex
* **관련 결정:** [ADR 0003](0003-smart-sync-merge-and-cold-start.md)

---

## 배경

테스트가 전혀 없는 신규 Node 프로젝트는 `npm run check`를 즉시 실행할 수 없어 결정론적 피드백 루프를 시작하기 어렵다. 반면 테스트 파일은 이미 있지만 `test` 스크립트가 없는 프로젝트에서는, Agentic이 러너와 패턴을 추측해 스크립트를 덮어쓰면 기존 테스트를 실행하지 못하게 만들 수 있다.

## 검토한 대안

1. 테스트 스크립트만 없으면 항상 Node 테스트 러너로 교체한다. 기존 테스트의 러너와 파일 패턴을 잘못 추측할 위험이 있어 채택하지 않는다.
2. 테스트 부트스트랩을 전혀 만들지 않는다. 완전히 빈 프로젝트가 검증 루프를 시작하지 못하므로 채택하지 않는다.
3. 테스트 스크립트와 알려진 테스트 파일이 모두 없을 때만 부트스트랩한다. 기존 구성을 보존하면서 빈 프로젝트를 지원하므로 채택한다.

## 결정

`init`과 `sync`는 다음을 모두 만족할 때만 테스트 구성을 자동 생성한다.

1. `package.json`의 `test` 스크립트가 없거나 npm 기본 오류 스크립트다.
2. 표준 테스트 디렉터리(`test`, `tests`, `__tests__`) 또는 일반적인 `*.test.*`·`*.spec.*` 파일이 감지되지 않는다.

이 경우에만 `node --test tests/**/*.test.mjs`와 `tests/smoke.test.mjs`를 추가한다. 스모크 테스트는 테스트 러너가 실행되는지만 증명하며, 제품 동작의 테스트나 품질 기준을 대체하지 않는다.

기존 테스트 흔적이 있으면 테스트 스크립트와 파일을 변경하지 않고, 사용자가 프로젝트에 맞는 테스트 명령을 설정하도록 경고한다.

## 결과

* 새 프로젝트는 외부 의존성 없이 최소 검증 루프를 시작할 수 있다.
* 기존 테스트 프레임워크·파일 배치·명령은 Agentic이 추측하거나 덮어쓰지 않는다.
* 테스트 수가 0개인지의 판정은 별도 검증 계약이 구현될 때까지 완료 조건으로 강제하지 않는다.
