# 0020. APM이 다시 만드는 파일에는 쓰지 않고, 하위 AGENTS.md마다 Claude Code 연결 파일을 만든다

* **상태:** 채택됨 (Accepted)
* **일자:** 2026-09-16
* **결정자:** 제품 소유자
* **근거:** [APM과 함께 쓰기 근거](../references.md#apm과-함께-쓰기-근거), [모노레포 연결 파일 근거](../references.md#모노레포-연결-파일-근거), [에이전트 지침 로드와 전달 확인 근거](../references.md#에이전트-지침-로드와-전달-확인-근거)
* **관련:** 연결 파일에도 [ADR 0008](0008-managed-conflict-recovery.md)의 관리 영역 hash와 base를 쓴다. [ADR 0019](0019-explain-verify-and-agent-skills.md)의 `explain`에 중복 경고를 더한다. [관리 산출물의 안전한 동기화](../discussion/architecture/topics/managed-artifact-safety.md) 논의의 "마커 없는 파일은 자동 덮어쓰지 않음"을 다른 도구가 다시 만드는 파일부터 적용한다.

## 배경 (Context)

- Microsoft APM 0.30.0은 처음 다섯 줄에 생성 표시가 있는 `AGENTS.md`·`CLAUDE.md`를 통째로 다시 만든다. agctx가 이런 파일에 관리 영역을 더하면, 다음 `apm compile`이 agctx의 내용을 지우거나 표시가 아래로 밀려 APM이 갱신을 멈춘다.
- APM의 `managed_section` 모드는 `<!-- apm:start -->`와 `<!-- apm:end -->` 사이만 바꾸므로, 그 블록을 agctx 확장 영역에 두면 두 도구를 함께 쓸 수 있다.
- Claude Code는 `CLAUDE.md`만 읽고 `AGENTS.md`는 가져오기로만 받는다. 패키지마다 `AGENTS.md`를 두는 모노레포에서 옆에 `CLAUDE.md`가 없으면 Claude Code는 그 패키지 규칙을 받지 않는다. 공개 모노레포 24곳을 조사하자 하위 `AGENTS.md` 151개 가운데 77개가 이런 상태였다. `explain`은 이를 알려 주지만 파일마다 사람이 고쳐야 했다.
- APM이 같은 규칙을 `AGENTS.md`와 `.claude/rules/`에 함께 넣는 것처럼, 같은 규칙이 두 경로로 들어가도 알아챌 방법이 없었다.

## 검토한 대안 (Options)

| 항목 | 대안 | 판단 |
| --- | --- | --- |
| APM 기본 모드 파일 | 지금처럼 관리 영역을 덧붙인다 | APM이 갱신을 멈추거나 agctx의 내용을 지운다 |
| | APM 내용을 표지로 감싸 자동으로 전환한다 | 다른 도구의 파일을 해석해 다시 쓰고, `apm.yml` 설정까지 바꿔야 해 조용한 실패가 생긴다 |
| | 쓰지 않고 멈춰 `managed_section` 전환을 안내한다 | **채택.** 실제 APM으로 안내 절차를 확인했다 |
| APM `managed_section` 블록 | 따로 알아보고 위치를 고정한다 | 프로젝트 영역 보존 규칙으로 이미 지켜진다 |
| | 프로젝트 영역의 내용으로 보고 그대로 둔다 | **채택.** 평가로 고정한다 |
| 하위 `AGENTS.md`와 Claude Code | `explain` 경고만 둔다 | 모노레포의 파일마다 사람이 고쳐야 한다 |
| | `.claude/rules/*.md`에 `paths`로 옮긴다(APM 방식) | 규칙 원본이 두 곳이 되고, 경로에 맞는 파일을 읽은 뒤에야 들어간다 |
| | 옆에 `@AGENTS.md`를 가져오는 관리 블록 `CLAUDE.md`를 만든다 | **채택.** 규칙 원본은 `AGENTS.md` 하나로 남는다 |
| 사람이 둔 `CLAUDE.md` | 관리 블록을 덧붙인다 | 사람이 정한 연결 방식(심볼릭 링크·직접 쓴 가져오기)을 바꾼다 |
| | 쓰지 않고, 가져오기가 없을 때만 경고한다 | **채택** |
| 하위 `AGENTS.md` 찾기 | 폴더를 모두 탐색한다 | 무시한 빌드 산출물의 `AGENTS.md`까지 잡는다 |
| | Git 저장소면 `git ls-files`(추적·미추적, 무시한 파일 제외), 아니면 의존성 폴더를 뺀 탐색 | **채택** |
| 중복 판정 | 파일 전체를 비교한다 | 일부만 복사한 경우를 놓친다 |
| | 규칙으로 보이는 줄이 3줄 이상 겹치면 경고한다 | **채택** |

## 결정 (Decision)

1. **APM 생성 파일:** `profile apply`·`profile sync`와 같은 계획을 쓰는 `profile resolve`·`check`·`repos sync`·`repos pr`은, 쓸 파일의 처음 다섯 줄에 APM 생성 표시가 있으면 아무 파일도 쓰지 않고 종료 코드 2와 오류 코드 `project.apm-generated`로 멈춘다. 표시는 `AGENTS.md`에는 `AGENTS.md` 표시 두 가지, `CLAUDE.md`에는 `<!-- Generated by APM CLI -->`만 본다. `AGENTS.md`면 `managed_section`으로 전환하는 절차를, `CLAUDE.md`면 파일을 옮기고 다시 적용하라고 안내한다.
2. **APM 블록:** `AGENTS.md`의 프로젝트 영역에 둔 `<!-- apm:start -->`~`<!-- apm:end -->` 블록은 agctx가 내용과 위치를 바꾸지 않으며, 관리 영역 hash에도 들어가지 않는다.
3. **연결 파일:** `apply`·`sync`는 프로젝트 루트 아래의 `AGENTS.md`마다, 같은 폴더에 `CLAUDE.md`가 없으면 `templates/CLAUDE.link.md`의 관리 블록(`@AGENTS.md`)으로 만들고 다른 관리 파일처럼 hash와 base를 기록한다.
   - 찾는 범위: 프로젝트가 Git 저장소 루트면 `git ls-files --cached --others --exclude-standard`, 아니면 폴더 탐색이다. 두 경우 모두 `node_modules`·`dist`·`build`·`vendor`·`.venv`·`target`·`coverage`·`.agctx`와 중첩된 Git 저장소를 뺀다.
   - 같은 폴더에 사람이 둔 `CLAUDE.md`나 `.claude/CLAUDE.md`(심볼릭 링크 포함)가 있으면 쓰지 않는다. 그 파일이 `AGENTS.md`를 가져오지 않으면 계획에 경고를 붙인다.
   - 관리하던 연결 파일 옆의 `AGENTS.md`가 없어지면 파일은 지우지 않고 관리 기록에서만 빼며 경고한다.
   - `repos sync`는 기록한 연결 파일도 커밋하지 않은 변경 검사에 넣는다.
4. **중복 경고:** `explain`은 한 에이전트에 들어가는 두 파일이 규칙으로 보이는 줄(24자 이상, 목록 기호를 뺀 뒤 제목·주석·가져오기가 아닌 줄)을 3줄 이상 함께 담으면 `warning`으로 알린다. 둘 가운데 하나는 세션 시작에 읽는 파일(`read`)이어야 하고, 다른 하나는 조건부(`conditional`·`on-demand`)여도 된다. 종료 코드는 바꾸지 않는다.

## 결과 및 영향 (Consequences)

- APM을 함께 쓰는 저장소가 어느 순서로 적용해도 조용히 깨지지 않는다. 모노레포는 `apply` 한 번으로 Claude Code가 패키지 규칙을 받는다.
- 평가: `evals/apm-coexistence.test.ts` 3개(두 도구의 번갈아 갱신, 기본 모드 파일에서 멈춤과 안내 절차, 아래쪽 표시는 내용으로 봄), `evals/monorepo-links.test.ts` 3개(연결 파일 생성과 사람 파일 보존·경고, sync의 추가·충돌·관리 해제, `repos sync`의 커밋하지 않은 변경 검사), `evals/explain.test.ts`의 중복 경고. 실제 apm-cli 0.30.0으로 두 적용 순서를 확인했다.
- 한계:
  - APM 표시와 판정 방식은 apm-cli 0.30.0 코드 기준이다. APM이 바꾸면 판정도 고쳐야 한다. APM 말고 다른 도구의 생성 파일은 알아보지 않는다.
  - 연결 파일은 Claude Code만을 위한 것이다. 하위 폴더에서 시작한 Claude Code가 루트 `CLAUDE.md`의 `@AGENTS.md`를 받으려면 여전히 프로젝트마다 한 번 승인해야 하고([ADR 0019](0019-explain-verify-and-agent-skills.md)), Antigravity는 하위 폴더 `AGENTS.md`를 세션 시작에 받지 않는다.
  - 연결 파일을 끄는 옵션은 두지 않는다. 연결하지 않을 폴더에는 사람이 `CLAUDE.md`를 두면 agctx가 쓰지 않지만, 그 파일이 `AGENTS.md`를 가져오지 않으면 적용할 때마다 경고가 나온다.
  - 중복 판정은 줄 문자열 비교라 표현만 다른 같은 규칙은 잡지 못한다.
  - APM 패키지 형식으로 내보내거나 읽는 연동은 하지 않는다.
