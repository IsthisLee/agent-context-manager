# 0022. 프로필이 담을 대상에 hooks를 더한다

* **상태:** 채택됨 (Accepted)
* **일자:** 2026-09-16
* **결정자:** 제품 소유자
* **근거:** 규칙과 hooks의 구분은 [기본 지침의 근거와 분량에 관한 자료](../references.md#기본-지침의-근거와-분량에-관한-자료)에 있다. 에이전트마다 hooks를 어디에 어떤 형식으로 두는지는 구현할 때 [프로필 설정 표면 확장](../discussion/architecture/topics/profile-config-surface.md) 논의에서 근거와 함께 정한다.
* **관련:** [ADR 0021](0021-profile-scope-skills-mcp-subagents.md)의 대상 목록에 hooks를 더한다. 0021의 "Hooks와 출력 스타일은 이 결정에 넣지 않는다" 가운데 hooks 부분을 대체하고, 출력 스타일을 넣지 않는 결정은 그대로 둔다.

## 배경 (Context)

- ADR 0021은 프로필이 담을 대상을 규칙·스킬·MCP·subagents로 정하고, hooks와 출력 스타일은 넣지 않았다.
- 규칙은 에이전트에게 권하는 글이고, 반드시 일어나야 하는 동작은 hooks가 맡는다. 참고 자료에 옮긴 Claude Code best practices도 지침은 권고이고 hooks는 동작을 보장한다고 구분한다.
- 팀은 규칙으로 정한 검증·보안 동작(예: 파일을 고친 뒤 포매터 실행, 위험한 명령 차단)을 hooks로 강제한다. hooks가 프로필 밖에 있으면 규칙은 같아도 실제로 강제되는 동작은 개발자마다 갈린다.

## 검토한 대안 (Options)

| 대안 | 판단 |
| --- | --- |
| hooks를 계속 범위 밖에 둔다 | 팀이 강제하려는 동작을 프로필로 나눠 줄 수 없다. 규칙은 같아도 강제되는 동작은 사람마다 다르다 |
| hooks를 확정 범위에 넣는다 | **채택.** 규칙과 그 규칙을 강제하는 동작을 한 프로필로 함께 공유한다 |
| hooks와 출력 스타일을 함께 넣는다 | 넣지 않는다. 출력 스타일은 무엇을 지키는지가 아니라 응답 방식(말투·형식)을 정하고, 설계안도 개인 취향에 가깝다고 보았다 |

## 결정 (Decision)

- 프로필이 담을 에이전트 컨텍스트는 규칙, 스킬, MCP 서버 설정, subagent 정의, hooks 다섯 가지다.
- 지금 구현된 것은 규칙뿐이다. 스킬·MCP·subagents·hooks는 확정된 범위지만 아직 동작하지 않으므로, README와 문서는 구현하기 전까지 현재 동작처럼 쓰지 않는다.
- hooks를 나눠 주는 일은 다른 개발자의 컴퓨터에서 실행될 동작을 나눠 주는 일이다. 그래서 구현할 때 다음 조건을 지킨다.
  - 적용·동기화로 hooks가 추가되거나 바뀌면, 실행될 내용을 그대로 보여 주고 확인을 받는다. 터미널이 아닌 곳에서는 [ADR 0016](0016-command-contract.md)대로 `--yes` 없이 진행하지 않는다.
  - 받은 프로필의 hooks도 숨은 문자 검사 대상이다.
  - 사람이 둔 hooks는 보존하고, agctx가 쓴 관리 영역을 손으로 고쳤으면 멈춘다.
  - agctx는 hooks를 실행하지 않는다. 설정을 전달할 뿐이다.
- 출력 스타일은 여전히 프로필 대상이 아니다.
- 구현 순서, 에이전트별 위치와 형식, 안전 병합 계약은 [프로필 설정 표면 확장](../discussion/architecture/topics/profile-config-surface.md) 논의에서 정한다.

## 결과 및 영향 (Consequences)

- 제품 방향 「범위와 경계」, README·README.en의 지향점·현재 범위·제안 단계 문장, 논의 문서의 대상 목록을 다섯 가지로 맞춘다.
- 논의 문서의 결정·검증 항목에 hooks의 확인·표시 조건을 더한다.
- 다섯 가지 중 무엇을 먼저 구현할지는 이 결정에서 정하지 않는다.
