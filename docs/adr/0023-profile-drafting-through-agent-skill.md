# 0023. 기존 저장소에서 프로필을 만들 때 초안은 사용자의 에이전트가 agctx 스킬 안내로 만든다

* **상태:** 채택됨 (Accepted)
* **일자:** 2026-09-16
* **결정자:** 제품 소유자
* **근거:** [프로젝트 지침 자동 생성에 관한 근거](../references.md#프로젝트-지침-자동-생성에-관한-근거)
* **관련:** [ADR 0006](0006-no-codebase-analysis-guidance.md)의 "분석 기능을 두지 않는다"를 기존 저장소에서 프로필을 만드는 경우에 한해 좁힌다. agctx가 모델을 호출하지 않는다는 [ADR 0001](0001-product-scope.md)의 경계와, 에이전트용 스킬을 배포한다는 [ADR 0019](0019-explain-verify-and-agent-skills.md)를 따른다. 기능 계약은 [기존 저장소에서 프로필 만들기](../discussion/architecture/topics/profile-import.md) 논의가 맡는다.

## 배경 (Context)

- 여러 저장소를 쓰는 사용자는 대개 한 저장소에 이미 규칙을 써 두었다. 그 저장소에서 프로필을 만드는 기능을 논의하면서, 에이전트가 저장소를 읽고 초안을 만들어 주면 좋겠다는 요구가 나왔다(2026-09-16 제품 소유자).
- ADR 0006은 agctx가 코드베이스를 분석해 지침을 작성하지 않고 초안은 각 에이전트의 `/init`에 맡긴다고 정했다. 근거는 코드에서 도출할 수 있는 저장소 개요가 과제 성공률을 높이지 못했다는 연구, 에이전트에 이미 있는 `/init`, 재현에서 드러난 초안 품질 문제였다.
- 프로필 초안은 프로젝트 지침 초안과 목표가 다르다. 저장소를 설명하는 글이 아니라 다른 저장소에도 쓸 규칙을 골라내는 일이고, 재료의 대부분은 이미 사람이 쓴 컨텍스트 파일이다.

## 검토한 대안 (Options)

| 대안 | 판단 |
| --- | --- |
| 복사만 한다 | 모델 호출이 없고 결과가 결정적이다. 그러나 어느 절을 옮길지, 저장소 이름·경로를 어떻게 일반화할지를 사람이 전부 판단해야 한다 |
| 복사하고, 초안은 사용자의 에이전트가 agctx 스킬 안내로 만든다 | **채택.** agctx에 모델 호출·인증·요금 처리가 생기지 않고, 사용자가 이미 쓰는 에이전트가 초안을 만든다 |
| 복사하고, agctx가 에이전트 CLI를 직접 실행해 초안을 만든다 | 한 명령으로 끝난다. 그러나 파일을 읽을 수 있는 에이전트를 agctx가 실행해야 해서 도구를 끄고 실행하는 `verify --probe`보다 권한이 넓고, 실행 확인·요금·가짜 CLI 테스트 부담이 생긴다 |

## 결정 (Decision)

- 기존 저장소에서 프로필을 만들 때 agctx는 컨텍스트 파일에서 고른 부분을 복사하고, 숨은 문자를 검사하고, 프로필에 저장하는 일만 한다. 이 과정에서 agctx는 모델을 호출하지 않고 에이전트를 실행하지 않는다.
- 초안은 사용자의 에이전트가 agctx 스킬 안내에 따라 만든다. 스킬은 다음 범위로 안내한다.
  - 이미 있는 컨텍스트 파일에서 다른 저장소에도 쓸 절을 고르고, 저장소 이름·경로 같은 부분을 일반적인 표현으로 바꾼 초안을 제안한다.
  - 코드를 읽을 때는 저장소 개요·디렉터리 구조·의존성 목록을 쓰지 않는다. 에이전트가 코드를 읽어 스스로 알기 어려운 비표준 관례와 함정 후보만 제안한다(ADR 0006의 판단 기준).
  - 초안은 사용자에게 보여 주기만 한다. 사용자가 고른 내용만 명시적인 agctx 명령으로 저장하고, 에이전트가 스스로 프로필에 저장하거나 `profile push`·`repos pr`을 실행하지 않는다.
- 코드베이스를 분석해 프로젝트 지침(`AGENTS.md`의 프로젝트 규칙 확장 영역)을 작성하지 않는다는 ADR 0006의 결정은 그대로다. 프로젝트 지침 초안은 계속 각 에이전트의 `/init`에 맡긴다.

## 결과 및 영향 (Consequences)

- ADR 0006은 기존 저장소에서 프로필을 만드는 경우에 한해 좁혀진다. README의 "지원하지 않는 기능"은 agctx 자체의 동작을 설명하므로, 이 기능을 구현하기 전까지 그대로 둔다.
- 스킬 안내를 따르는지는 모델의 판단이라 보장된 동작이 아니다. 그래서 저장은 사람이 고른 내용만 받는 CLI 명령으로 제한하고, 저장한 프로필도 `profile push`·`repos pr` 전에 사람이 검토한다.
- 에이전트가 읽는 저장소 파일은 믿을 수 없는 입력이다. agctx는 저장할 내용을 `profile clone`과 같은 숨은 문자 검사에 통과시킨다.
- 명령 형태, 나누는 단위, 원래 저장소에 남는 중복의 처리, 스킬 안내 문구는 논의 문서에서 정한다.
