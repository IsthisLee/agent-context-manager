# 0025. 모든 명령은 CLI와 TUI에서 실행할 수 있어야 한다

* **상태:** 채택됨 (Accepted)
* **일자:** 2026-09-17
* **결정자:** 제품 소유자
* **근거:** 외부 근거 없음: 이 패키지가 사용자에게 제공할 실행 경로에 관한 결정이며, 외부 도구의 동작이나 표준에 기대지 않는다.
* **관련:** [ADR 0016](0016-command-contract.md)의 결정 6(동등성 기준)과 [ADR 0018](0018-multi-repository-sync.md)의 결정 7(`repos` 명령의 필수 경로)을 대체한다. 등록부·종료 코드·JSON 출력·변경 확인 계약은 ADR 0016 그대로다. 정본 계약은 [구현 계약](../discussion/architecture/topics/implementation-contracts.md#인터페이스-동등성)의 "인터페이스 동등성" 절이다.

## 배경 (Context)

- ADR 0016은 `profile` 명령에만 CLI·TUI·프로필 관리 메뉴 세 경로를 요구하고, `repository`·`global` 명령은 CLI만 필수로 두었다. 프로필 관리 메뉴는 프로필 하나를 고른 뒤의 화면이라 저장소를 다루는 명령을 넣을 자리가 없었기 때문이다. 첫 화면 TUI까지 필수에서 뺀 이유는 기록되지 않았다.
- 그래서 TUI로 쓰는 사람도 적용 결과를 확인하거나(`check`·`explain`·`verify`) 여러 저장소를 맞출 때(`repos list`·`sync`·`pr`)는 명령과 옵션을 외워야 했다. `profile clone`·`connect`의 `--branch`처럼 TUI가 묻지 않는 옵션도 있었다.
- 2026-09-17에 남은 명령의 TUI 메뉴를 구현해 모든 명령을 TUI에서 실행할 수 있게 됐다. 하지만 계약은 여전히 CLI만 요구해, 새 명령이 TUI 없이 추가돼도 검사가 막지 못했다.

## 검토한 대안 (Options)

| 대안 | 판단 |
| --- | --- |
| 지금처럼 `repository`·`global` 명령은 CLI만 필수로 둔다 | 새 명령이 TUI 없이 추가돼도 검사가 막지 못하고, TUI 사용자가 다시 명령을 외워야 한다 |
| 모든 명령에 CLI·TUI·프로필 관리 메뉴 세 경로를 요구한다 | 프로필 하나를 고른 뒤 `check`나 도움말을 실행하는 흐름은 뜻이 맞지 않는다 |
| 모든 명령에 CLI와 TUI를 요구하고, 프로필 관리 메뉴는 `profile` 명령에만 요구한다 | **채택.** 프로필 관리 메뉴의 뜻을 지키면서 TUI 사용자가 모든 기능을 쓸 수 있다 |

## 결정 (Decision)

1. **필수 경로:** 모든 명령은 CLI 명령·옵션과 TUI에서 실행할 수 있어야 한다. `profile` 명령은 `agctx profile list`의 프로필 관리 메뉴에서도 실행할 수 있어야 한다.
2. **등록부:** `src/commands/registry.ts`의 `CommandSpec.tui`는 필수 필드다. 그 키는 첫 화면 메뉴(`MAIN_MENU_ENTRIES`), 프로필 관리 메뉴, 프로젝트 점검·여러 저장소 메뉴 가운데 한 곳에 보이는 항목이어야 한다. `evals/interface-parity.test.ts`가 명령마다 이를 검사하고, 첫 화면 항목마다 동작이 연결됐는지도 검사한다.
3. **같은 동작:** 명령의 옵션을 질문으로 받는 흐름은 답을 CLI 토큰으로 바꿔 CLI와 같은 옵션 검사와 처리기로 실행한다(`src/tui/commands.ts`). 그래서 변경 확인도 CLI와 같이 처리기 안에서 묻는다. 프로필 만들기·지침 설정·삭제·충돌 해결처럼 TUI가 단계마다 묻는 흐름은 CLI 처리기가 부르는 것과 같은 도메인 함수를 부른다. 어느 쪽이든 TUI가 CLI에 없는 동작을 만들지 않는다.
4. **TUI에 요구하지 않는 옵션:** 사람이 화면을 보며 답하는 경로이므로 `--json`, `--yes`, 단독 `--dry-run`, 한 번만 쓰는 `--lang`은 TUI에 요구하지 않는다. TUI는 대신 계획을 보여 준 뒤 확인을 묻고, 결과 줄과 종료 코드의 뜻을 보여 준다. 그 밖의 옵션은 질문으로 받는다.
5. **예외:** TUI로 옮길 수 없는 명령이 생기면 새 ADR로 예외와 이유를 정한 뒤 등록부 계약을 바꾼다.

## 결과 및 영향 (Consequences)

- 명령을 더하려면 CLI 처리기와 함께 TUI 항목과 동작을 만들어야 한다. `tui`를 빠뜨리면 형식 검사가, 메뉴에 보이지 않으면 동등성 평가가 실패한다.
- CLI Reference 명령 표의 "쓸 수 있는 곳" 열은 등록부의 `tui`·`profileMenu`에서 생성한다([문서 게이트](../contributing/doc-gate.md#생성하는-레퍼런스)).
- `AGENTS.md`의 "기능 인터페이스 동등성" 규칙을 이 결정에 맞춘다.
- 한계: 동등성 평가는 항목이 메뉴에 보이고 동작이 연결됐는지만 확인한다. 흐름이 명령의 옵션을 모두 묻는지는 `evals/tui-commands.test.ts`의 답과 옵션 대응 검사와 TUI를 직접 실행한 확인으로 본다.
