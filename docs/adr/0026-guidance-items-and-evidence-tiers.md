# 0026. 지침 항목을 열 개로 나누고 근거 등급을 세 단계로 넓힌다

* **상태:** 채택됨 (Accepted)
* **일자:** 2026-09-18
* **결정자:** 제품 소유자
* **근거:** [기본 지침 문장의 근거](../references.md#기본-지침-문장의-근거), [기본 지침의 근거와 분량에 관한 자료](../references.md#기본-지침의-근거와-분량에-관한-자료)
* **관련:** [ADR 0024](0024-guidance-evidence-and-budget.md)의 근거 등급과 분량 예산을 넓힌다. 채택 조건 네 가지와 카탈로그 근거 열 강제는 그대로다. [ADR 0005](0005-guidance-level-semantics.md)의 "적용 수준마다 문구는 하나"도 그대로다. 계약과 남은 작업은 [기본 지침의 근거 기준과 분량 예산](../discussion/architecture/topics/guidance-evidence-and-budget.md) 논의가 맡는다.

## 배경 (Context)

- ADR 0024로 여섯 항목을 근거 있는 문구로 다시 쓴 뒤, 근거 문서 18건을 전문으로 다시 읽으며 문장 단위로 대조했다. 그 결과 세 가지가 드러났다.
- **항목이 뭉쳐 있었다.** "작업 흐름"은 계획·완료 기준·범위·중단에 더해 서브에이전트와 컨텍스트 관리까지 담았고, "보안"은 비밀값·권한·승인에 프롬프트 인젝션 대응까지 담았다. 근거 문서도 서로 달라, 사용자가 필요한 부분만 고르기 어려웠다.
- **근거 등급이 좁았다.** 0024는 공급사 공식 문서와 표준 기관 문서만 단독 근거로 인정했다. 그래서 어떤 실천법을 만든 사람의 1차 저작(Kent Beck의 TDD, Martin Fowler의 정의)은 이름의 출처로만 쓸 수 있었다.
- **빠진 것과 넘친 것이 있었다.** 전문 재독에서 근거에 있는데 문구에 없는 것(같은 정정을 반복하면 지침에 더한다, 조사 범위를 좁힌다, 예상치 못한 입력)과, 근거를 넘어 쓴 것(평가자 하나에 대한 문장을 서브에이전트 전반으로 넓힘, 없는 횟수 "두세 번", 원문에 없는 "출력")을 찾았다.
- 사용자가 팀 관례로 쓰는 문서화와 응답 언어를 항목으로 요청했다. 문서화는 A급 근거를 찾았지만, 응답 언어를 고정하라는 권고는 어느 공식 문서에도 없다.

## 검토한 대안 (Options)

| 대안 | 판단 |
| --- | --- |
| 항목 여섯 개를 유지하고 문장만 늘린다 | 한 항목이 서로 다른 근거의 규칙을 담아, 필요한 부분만 골라 쓸 수 없다 |
| 뭉친 항목을 나누고 요청받은 두 항목을 더해 열 개로 만든다 | **채택.** 근거 문서가 갈리는 지점에서 나눴다 |
| 근거 등급을 A와 보조 두 단계로 유지한다 | 실천법을 만든 사람의 1차 저작이 정의를 가장 정확히 적는데도 쓸 수 없다 |
| 세 단계로 넓히고, 효과 주장은 A급만 인정한다 | **채택.** 이 분야 연구는 결과가 엇갈려 효과 주장을 열면 틀린 문장을 배포할 수 있다 |
| 근거 없는 항목은 넣지 않는다 | 응답 언어는 팀이 실제로 필요로 하는데 공식 권고가 없다. 기본값을 `off`로 두는 예외로 해결한다 |

## 결정 (Decision)

### 항목 열 개

| 옵션 | 항목 | 기본값 | 근거가 갈리는 지점 |
| --- | --- | --- | --- |
| `--workflow` | 작업 흐름 | `recommended` | 계획·완료 기준·범위·중단 |
| `--context` | 맥락 관리 | `recommended` | 서브에이전트와 컨텍스트 엔지니어링 |
| `--tdd` | TDD | `recommended` | Red-Green-Refactor와 테스트 무결성 |
| `--review` | 변경 검토 | `recommended` | 분리된 맥락의 검토 |
| `--verification` | 검증 | `recommended` | 확인 실행과 증거 |
| `--instructions` | 지침 파일 | `recommended` | 지침 파일에 무엇을 두는가 |
| `--docs` | 문서화 | `recommended` | 정본과 링크, 완료 표기 |
| `--security` | 보안 | `recommended` | 비밀값·권한·승인·의존성 |
| `--untrusted` | 믿을 수 없는 입력 | `recommended` | 프롬프트 인젝션과 도구·MCP |
| `--language` | 응답 언어 | `off` | 근거 없음(아래 예외) |

- 항목을 나누는 기준은 근거 문서다. 한 항목의 문장들이 서로 다른 문서에서 나오고 사용자가 따로 켜고 끌 이유가 있으면 나눈다.
- 응답 언어는 값을 따로 받지 않고 프로필 로케일(`ko`·`en`)에 맞는 문장을 쓴다. 프로필 언어와 다른 언어로 답하게 하려면 guidance 블록 밖에 직접 쓴다.

### 근거 등급 세 단계

| 등급 | 종류 | 단독 근거로 쓸 수 있는 범위 |
| --- | --- | --- |
| A | 에이전트 제공사의 공식 문서와 공식 엔지니어링 글, 표준 기관의 기술 문서(OWASP 등) | 정의·절차·효과 주장 모두 |
| B | 그 실천법을 만든 사람의 1차 저작, 방법과 결과를 공개한 동료 심사 연구, 공공기관 보고서 | 정의·용어·절차만. 효과 주장에는 A와 함께여야 한다 |
| C | 블로그, 영상, 포럼, 다른 도구의 규칙 | 단독으로 쓰지 않는다. A·B 문장을 보강하거나 이름의 출처를 밝히는 데만 쓴다 |

- 효과 주장을 A급으로 묶는 이유는 이 분야 연구가 엇갈리기 때문이다. `references.md`에 기록된 두 연구가 컨텍스트 파일의 효과에 대해 서로 다른 방향을 가리킨다.
- 대상이 다른 글에서 원칙을 가져오면 그 사실을 `references.md`에 밝힌다. 에이전트 시스템을 만드는 사람이나 프롬프트를 쓰는 사람에게 한 말을 에이전트 자신의 규칙으로 옮긴 경우가 그렇다.
- 원문이 권고인데 배포 문구에서 명령형으로 옮겼으면 그 사실도 밝힌다.

### 응답 언어 항목의 예외

- 응답 언어는 A·B급 근거가 없다. 공식 문서가 정하는 것은 "이런 관례를 어디에 두는가"까지다.
- 그래서 이 항목만 "근거 없는 문장은 기본 지침에 넣지 않는다"의 예외로 둔다. 조건은 두 가지다. 기본값을 `off`로 두어 켜는 사람만 받고, 지침 카탈로그의 근거 열에 근거가 없다는 사실을 적는다.
- 이 예외는 응답 언어 한 항목에만 적용한다. 다른 항목을 근거 없이 더하려면 새 ADR이 필요하다.

### 분량 예산

- 모든 항목을 `strict`로 켠 guidance 블록은 **120줄·10 KiB 이하**다(0024의 100줄·8 KiB를 넓힌다). Codex 한도 32 KiB의 3분의 1 미만이고, Claude Code가 권하는 200줄의 60% 이내다.
- 예산은 짧게 쓰라는 뜻이 아니다. Anthropic은 최소가 곧 짧음은 아니며 원하는 동작을 지키게 하려면 충분한 정보를 주어야 한다고 적는다. 예산이 지키는 것은 사용자와 프로젝트 지침이 쓸 공간이다.
- 평가가 ko·en 모두를 검사한다. 항목 수는 `GUIDANCE_KEYS`를 읽으므로 항목을 더하면 카탈로그 행 수 검사도 함께 따라간다.

## 결과 및 영향 (Consequences)

- **호환성 파괴:** `profile setup`에 옵션 네 개(`--context`·`--docs`·`--untrusted`·`--language`)가 늘어난다. 옵션을 순서대로 읽는 비대화형 표준 입력은 줄이 여섯에서 열로 늘어나므로, 여섯 줄을 넘기던 스크립트는 나머지 항목이 기본값으로 만들어진다. 기존 프로필에 저장된 여섯 항목의 값은 그대로 읽는다.
- 문구가 바뀌어도 기존 프로필은 자동으로 바뀌지 않는다. `profile setup`을 다시 실행하면 guidance 블록이 바뀌고 `profile sync`로 프로젝트에 반영된다. 블록 밖에 쓴 내용은 그대로 남는다.
- 항목을 더하거나 문구를 고칠 때는 [지침 카탈로그](../reference/guidance-catalog.md), `src/i18n/index.ts`, `references.md`를 같은 변경에서 고친다.
- 리뷰어를 subagent로 배포하게 되면 "변경 검토" 항목의 점검 목록은 그 프롬프트로 옮길 수 있다. subagent의 설명만 메인 대화에 상시 로드되고 본문은 호출될 때만 로드되기 때문이다. 다만 형식이 확인된 에이전트가 하나뿐이라 지금은 옮기지 않고, [프로필 설정 표면 확장](../discussion/architecture/topics/profile-config-surface.md) 논의의 후속 작업으로 둔다.
