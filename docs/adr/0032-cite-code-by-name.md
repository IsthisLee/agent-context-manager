# 0032. 문서는 코드를 파일과 이름으로 가리킨다

* **상태:** 채택됨 (Accepted)
* **일자:** 2026-09-20
* **결정자:** 제품 소유자
* **근거:** [문서와 코드의 드리프트 검출 근거](../references.md#문서와-코드의-드리프트-검출-근거)
* **관련:** [문서가 코드를 인용하는 방식](../discussion/repository/topics/code-citation-style.md) 논의의 결정을 확정한다. [문서 소스 해시 게이트](../contributing/doc-gate.md#문서-소스-해시-게이트)는 유지하되 지키는 대상이 줄어든다.

## 배경 (Context)

- 문서가 코드를 세 가지 방식으로 복사했다. `파일:줄` 인용 311개(`implementation-mechanics.md` 210, `implementation-principles.md` 101), 코드 발췌 45개, 동작을 말로 다시 적은 문장이다.
- 복사본은 코드가 바뀔 때마다 따로 고쳐야 하므로 해시 게이트가 자주 울렸다. 소스 파일 하나를 고치면 문서 중앙값 6개가 걸렸고, 주석 한 줄에도 문서 9개가 걸렸다.
- 자주 울리니 읽지 않고 지문만 다시 찍게 됐다. 두 문서의 재기록 31번 중 10번이 지문만 바꿨고, 고친 133줄 중 51줄(38%)은 줄 번호 숫자만 바꾼 줄이었다.
- 그 결과 게이트가 통과하는 상태에서도 이름이 함께 적힌 인용 115개 중 10개가 틀려 있었다. `implementation-mechanics.md`의 22절은 코드 발췌·줄 번호·설명이 한꺼번에 옛 상태로 남았다.
- 같은 내용을 코드 옆 주석에 적은 쪽은 맞는 상태였다. 코드를 고친 변경에서 주석도 함께 고쳐졌기 때문이다.

## 검토한 대안 (Options)

| 대안 | 판단 |
| --- | --- |
| 지금 유지하고 게이트만 절 단위로 좁힌다 | 경보 범위는 줄지만 복사본이 그대로라, 코드 위에 줄이 하나만 생겨도 그 아래를 인용한 문서가 계속 걸린다 |
| 줄 번호만 이름으로 바꾸고 발췌와 설명은 둔다 | 숫자 맞추기는 없어지지만, 발췌와 설명이 틀어지는 것을 잡는 방법은 여전히 사람이 다시 읽는 것뿐이다 |
| fiberplane/drift를 도입한다 | 지문에 위치가 없어 줄 번호가 밀리는 변화를 놓친다. 인용을 이름으로 바꾸고 나면 이름이 있는지만 확인하면 되므로 별도 실행 파일이 필요 없다 |
| **복사하지 않고 가리킨다** | **채택.** 복사본 자체를 없애면 고칠 곳과 울릴 이유가 함께 줄고, 남는 인용은 기계가 검사할 수 있다 |

## 결정 (Decision)

- 문서는 코드를 `` `src/check.ts`의 `checkProject` ``처럼 **파일과 그 안의 이름**으로 가리킨다. 줄 번호와 코드 발췌는 쓰지 않는다.
- `check:docs`가 두 가지를 검사한다. 저장소가 소유한 파일을 줄 번호로 인용하면 실패하고, 가리킨 이름이 그 파일에 없으면 실패한다.
- 이력을 남기는 `docs/discussion/`·`docs/adr/`·`CHANGELOG.md`와 코드 블록 안의 예시는 대상이 아니다.
- 코드가 무엇을 하는지는 코드와 그 옆 주석이, 왜 그런지는 ADR이 정본이다. 문서는 그 위치를 가리키고 이유로 링크한다.
- `implementation-mechanics.md`는 기능마다 위치·이유·검사를 가리키는 안내도로 줄이고, `implementation-principles.md`는 학습용 설명을 유지하되 인용만 이름으로 바꾼다.

## 결과 및 영향 (Consequences)

- 줄 번호 인용이 311개에서 0개가 됐다. 대신 기계가 검사하는 이름 인용 217개가 남았다. `implementation-mechanics.md`는 901줄에서 291줄로, 코드 발췌는 39개에서 0개로 줄었다(남은 코드 블록 하나는 모듈 지도 그림이다).
- `implementation-mechanics.md`는 코드를 서술하지 않으므로 소스 해시 마커를 떼었다. 그 파일들은 `architecture.md`가 계속 핀한다.
- 이름으로 가리킬 수 없는 동작(함수 안의 특정 분기 등)은 그 동작을 보장하는 평가의 이름으로 가리킨다. 이 방법은 아직 규칙으로 정하지 않았다.
- "정확히 몇 번째 줄"이라는 정보가 사라진다. 이름은 편집기의 심볼 찾기나 `rg`로 찾는다. GitHub에서는 원래 줄 번호 인용도 링크가 아니라 글자였다.
- 문서 게이트는 남은 서술 문장을 계속 지킨다. 핀 범위를 절 단위로 좁히는 [개편](../discussion/repository/topics/doc-gate-pin-scope.md)은 이 결정 뒤의 상태를 기준으로 다시 정한다.
