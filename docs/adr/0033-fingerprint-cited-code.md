# 0033. 인용한 코드의 지문으로 변경을 검출한다

* **상태:** 채택됨 (Accepted)
* **일자:** 2026-09-20
* **결정자:** 제품 소유자
* **근거:** [문서와 코드의 드리프트 검출 근거](../references.md#문서와-코드의-드리프트-검출-근거)
* **관련:** [ADR 0032](0032-cite-code-by-name.md)가 정한 인용 형식을 그대로 두고 검사만 넓힌다. [문서 소스 해시 게이트](../contributing/doc-gate.md#문서-소스-해시-게이트)는 남은 서술 문장을 계속 지킨다.

## 배경 (Context)

- [ADR 0032](0032-cite-code-by-name.md)로 인용을 `파일`의 `이름`으로 바꾸고, `check:docs`가 그 이름이 파일에 있는지 검사하게 했다.
- 그 검사는 **이름이 사라졌을 때만** 걸린다. 이름이 그대로면 그 함수의 내용이 통째로 바뀌어도 문서를 다시 읽게 하지 못한다.
- 같은 변경에서 `implementation-mechanics.md`의 소스 해시 마커를 뗐으므로, 그 문서의 설명 문장은 어떤 자동 검사도 지키지 않는 상태가 됐다.
- 외부 도구 [fiberplane/drift](https://github.com/fiberplane/drift)는 이 문제를 심볼 지문으로 푼다. 다만 지문에 위치를 넣지 않아 줄 번호가 밀리는 변화는 놓치며, 별도 실행 파일을 설치해야 한다([근거](../references.md#문서와-코드의-드리프트-검출-근거)).
- 우리 저장소의 TypeScript는 7.0.2이고, 이 버전의 JavaScript API는 `version`만 내보내며 파서를 제공하지 않는다(2026-09-20 실측). 정확한 AST 파서를 쓰려면 새 의존성이 필요하다.

## 검토한 대안 (Options)

| 대안 | 판단 |
| --- | --- |
| 이름 존재 검사만 유지하고 나머지는 리뷰에 맡긴다 | 채택하지 않는다. 정책이나 구조가 바뀌어 설명이 틀려도 아무도 알려 주지 않는다. 같은 종류의 사고가 이미 있었다 |
| fiberplane/drift를 도입한다 | 채택하지 않는다. 인용 217곳을 drift 앵커 형식으로 다시 쓰고 CI와 기여자 컴퓨터에 바이너리를 설치해야 하며, 생성·실행 대조·문서 계약 검사는 여전히 우리 코드가 맡는다 |
| 문서에 소스 해시 마커를 다시 단다 | 채택하지 않는다. 파일·폴더 단위라 관련 없는 변경에도 문서 전체가 걸린다. 이 소음이 지문만 다시 찍는 습관을 만들었다 |
| **인용마다 지문을 기록한다** | **채택.** 인용 형식을 그대로 두고 실패 단위를 항목 하나로 좁힌다 |

## 결정 (Decision)

- 인용 옆에 가리킨 코드의 지문을 HTML 주석으로 기록한다. 사람이 쓰지 않고 `node tools/check-docs.ts --stamp`가 붙인다.
- 지문은 대상을 파일에서 잘라 내 계산한다. TypeScript는 최상위 선언 한 덩어리, JSON은 그 키의 값, YAML은 그 키의 블록이다. 다른 Markdown 문서를 가리키는 인용은 지문을 붙이지 않는다.
- 잘라 내는 일은 새 의존성 없이 얕은 파서가 한다. 인용한 이름을 모두 잘라 낼 수 있는지는 평가가 검사한다.
- 가리킨 코드가 바뀌면 그 문서의 그 항목만 실패한다.

## 결과 및 영향 (Consequences)

- 인용 212곳에 지문이 기록됐다. 문서 원문에는 주석이 늘지만 렌더링에는 보이지 않는다.
- 실패 범위가 좁아졌다. `src/check.ts`의 `checkProject`에 주석 한 줄을 넣어 보니 지문 검사는 `implementation-mechanics.md`의 해당 항목 두 곳을 지목했고, 같은 변경에 소스 해시 게이트는 문서 7개를 통째로 걸었다(2026-09-20 실측).
- 얕은 파서는 이 저장소의 작성 방식(최상위 선언, 들여쓰기로 구분되는 JSON·YAML 키)에 기댄다. 그 방식을 벗어난 코드를 인용하면 평가가 실패하므로 다른 이름을 가리키거나 파서를 손봐야 한다.
- 지문이 바뀌었다고 해서 문서가 틀렸다는 뜻은 아니다. 게이트는 다시 읽으라고 알릴 뿐이며, 고칠 것이 없으면 `--stamp`로 다시 기록한다.
