# 0039. 코드·JSON·YAML의 서식을 Prettier로 맞추고 Markdown은 뺀다

* **상태:** 채택됨 (Accepted)
* **일자:** 2026-09-22
* **결정자:** 제품 소유자
* **근거:** 외부 근거 없음: 이 저장소에서 잰 값(바뀌는 줄 수, 문서 검사 실패 수)으로 정한 결정이다.

## 배경 (Context)

- 저장소에 서식 도구가 없었다. `.editorconfig`는 인코딩, 줄 끝, 들여쓰기만 정하고, 따옴표와 줄 폭, 끝 쉼표는 정하지 않았다. 2026-09-22에 잰 TypeScript 15,062줄 가운데 120자를 넘는 줄이 1,049줄, 160자를 넘는 줄이 322줄이었다.
- 서식을 검사하는 단계가 없어서, 편집기와 에이전트마다 다른 서식이 그대로 커밋될 수 있었다.

## 검토한 대안 (Options)

바뀌는 줄 수는 2026-09-22 `main`(`1168012`)의 TypeScript 파일에 Prettier 3.9.8을 옵션만 바꿔 실행하고 `git diff --shortstat`으로 쟀다.

| 항목 | 대안 | 판단 |
| --- | --- | --- |
| 대상 | 코드·JSON·YAML | **채택** |
| | Markdown까지 | 문서 102개에서 1,877줄이 더해지고 1,808줄이 빠진다. 목록 들여쓰기, 표 정렬, 목록 기호가 바뀌어 `check:docs`가 84건 실패한다. 대부분 논의 문서의 제안 요약 필드를 찾지 못한 실패다 |
| 따옴표·끝 쉼표·화살표 괄호 | 지금 코드의 관례(작은따옴표, 끝 쉼표 없음, 매개변수 하나면 괄호 생략) | **채택.** 폭 120에서 5,759줄 추가, 2,219줄 삭제로 가장 적게 바뀐다 |
| | 끝 쉼표를 붙이고 괄호를 항상 쓴다 | 폭 120에서 6,271줄 추가, 2,716줄 삭제 |
| 줄 폭 | 100 | 8,624줄 추가, 2,804줄 삭제 |
| | 120 | **채택** |
| | 160 | 3,252줄 추가, 1,721줄 삭제로 가장 적게 바뀌지만, 두 파일을 나란히 비교하는 diff 화면에서 줄이 잘린다 |

폭 120은 바뀌는 줄 수와 diff 화면의 가독성 사이에서 고른 판단이다.

## 결정 (Decision)

1. Prettier 3.9.8을 개발 의존성으로 고정한다. `.prettierrc.json`은 폭 120, 작은따옴표, 끝 쉼표 없음, 매개변수 하나인 화살표 함수의 괄호 생략이고, YAML만 큰따옴표를 쓴다. `main`의 YAML에서 따옴표로 감싼 값은 큰따옴표 2줄(`openai.yaml`)과 작은따옴표 1줄(`codeql.yml`)이라 큰따옴표로 맞추는 쪽이 덜 바뀐다.
2. `.prettierignore`로 Markdown과 `pnpm-lock.yaml`을 뺀다. Markdown은 문서 계약 검사(`check:docs`)가 맡는다.
3. `pnpm run format`이 서식을 맞추고, `pnpm run format:check`가 검사한다. `pnpm run check`는 형식 검사 다음에 서식 검사를 실행하므로 CI에서도 강제된다.
4. 도입할 때 저장소 전체를 한 번 포맷한다. 이때 서식만 바뀐 코드를 가리키는 문서의 지문과 소스 해시는 한 번에 다시 기록한다.

## 결과 및 영향 (Consequences)

- 도입 변경은 서식만 바꾼다. Prettier의 `--debug-check`로 `main`의 원본 93개 파일을 포맷한 결과가 원본과 같은 AST를 갖는 것을 확인했다.
- 코드를 고친 사람과 에이전트는 `pnpm run format`을 실행한다. 빠뜨리면 `pnpm run check`와 CI가 실패한다.
- Markdown의 서식은 계속 손으로 맞춘다. Markdown을 대상에 넣으려면 먼저 `check:docs`의 제안 요약 파서와 문서 생성 도구가 Prettier가 만드는 목록 모양을 받아들여야 한다.
- 도입 커밋이 거의 모든 코드 줄의 `git blame`을 덮는다. 병합한 뒤 `.git-blame-ignore-revs`에 그 커밋을 더해 거른다.
