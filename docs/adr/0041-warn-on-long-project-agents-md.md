# 0041. 프로젝트 `AGENTS.md`가 200줄을 넘거나 24 KiB 이상이면 적용할 때 경고만 한다

* **상태:** 채택됨 (Accepted)
* **일자:** 2026-09-22
* **결정자:** 제품 소유자
* **근거:** [기본 지침의 근거와 분량에 관한 자료](../references.md#기본-지침의-근거와-분량에-관한-자료)
* **관련:** [ADR 0024](0024-guidance-evidence-and-budget.md)는 agctx가 배포하는 기본 지침 블록의 예산을 정했다. 이 ADR은 사용자와 프로젝트가 쓴 부분까지 합친 프로젝트 `AGENTS.md` 전체의 경고를 정한다. 논의는 [기본 지침의 근거 기준과 분량 예산](../discussion/architecture/topics/guidance-evidence-and-budget.md#분량-예산과-경고)에 있다.

## 배경 (Context)

- Claude Code는 지침 파일마다 200줄 미만을 목표로 권하고, 긴 파일은 준수율을 낮춘다고 설명한다. Codex는 지침 파일을 합친 크기가 `project_doc_max_bytes`(기본 32 KiB)에 이르면 파일을 더 넣지 않는다.
- 프로젝트 `AGENTS.md`의 확장 영역은 사용자 것이라 agctx가 줄이거나 옮기지 않는다. 그래서 규칙이 쌓여 기준을 넘어도 지금까지는 아무도 알려 주지 않았다.
- UTF-8에서 한글 한 글자는 3바이트라서, 긴 줄이 많은 한국어 지침은 줄 수보다 바이트 기준에 먼저 닿는다.

## 검토한 대안 (Options)

| 대안 | 판단 |
| --- | --- |
| 경고만 한다 | **채택.** 사용자 내용을 건드리지 않고, 결정론적으로 잴 수 있다 |
| 기준을 넘으면 적용을 멈춘다 | 기준은 권고와 기본 설정값이라 넘어도 동작하는 프로젝트가 있다. 멈추면 사용자가 자기 규칙을 지우기 전까지 프로필 갱신을 받지 못한다 |
| 넘는 부분을 별도 문서로 옮긴다 | 무엇을 옮길지 고르려면 내용을 이해해야 해서 모델 호출이 필요하다([ADR 0006](0006-no-codebase-analysis-guidance.md)과 같은 범위 문제) |
| `check`에서도 알린다 | `check`는 CI가 막는 기준(충돌·뒤처짐·숨은 문자)을 보고한다. 권고를 넘은 분량은 막을 이유가 아니라서 넣지 않는다 |

## 결정 (Decision)

1. `profile apply`·`profile sync`·`repos sync`는 이번에 쓸 프로젝트 `AGENTS.md` 전체(프로필 영역과 확장 영역)가 200줄을 넘거나 24 KiB(24,576바이트) 이상이면 경고한다. 24 KiB는 Codex 기본 한도의 75%다. 두 기준을 모두 넘으면 경고가 두 개 나온다.
2. 파일에 쓰일 형태로 잰다. 이미 CRLF로 저장된 파일은 CRLF로 다시 쓰이므로 줄마다 한 바이트를 더한다.
3. 경고만 한다. 파일 내용과 종료 코드는 바뀌지 않는다. 경고는 stderr로 나가고 `--json`이면 `warnings`에 담긴다. 충돌로 멈춘 `--json` 결과에도 멈추기 전에 보여 준 경고를 담는다.
4. 경고 문구는 이미 쓴 파일이 아니라 이번에 쓸 내용을 말한다. `--dry-run`이나 거절한 실행에서는 디스크의 파일과 숫자가 다를 수 있기 때문이다.

## 결과 및 영향 (Consequences)

- 확장 영역에 규칙을 쌓는 사용자는 적용할 때마다 기준을 넘었다는 안내를 받는다. 줄이지 않아도 적용은 그대로 진행된다.
- 고정한 저장소, 커밋하지 않은 관리 파일이 있는 저장소, 충돌한 저장소는 `repos sync`가 쓰지 않으므로 경고도 나오지 않는다.
- 필요할 때만 읽히는 형태로 지침을 옮기는 기능이 생기면 경고가 그 기능을 가리키게 고친다. 그 기능은 [프로필 설정 표면 확장](../discussion/architecture/topics/profile-config-surface.md)에서 다룬다.
