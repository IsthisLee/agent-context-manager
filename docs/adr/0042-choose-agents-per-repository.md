# 0042. 저장소마다 파일을 받을 에이전트를 골라 `agctx.project.json`에 기록한다

* **상태:** 채택됨 (Accepted)
* **일자:** 2026-09-22
* **결정자:** 제품 소유자
* **근거:** 외부 근거 없음: agctx가 쓰는 파일과 기록의 계약을 정하는 결정이다. 에이전트가 어떤 파일을 읽는지는 [ADR 0011](0011-supported-agents.md)과 [ADR 0035](0035-claude-code-reads-agents-md.md)가 다룬다.
* **관련:** [ADR 0011](0011-supported-agents.md)(지원 에이전트), [ADR 0016](0016-command-contract.md)(명령 계약), [ADR 0025](0025-every-command-in-cli-and-tui.md)(CLI·TUI 동등성). 논의는 [적용할 에이전트와 대상 종류 고르기](../discussion/architecture/topics/apply-selection.md)에 있다.

## 배경 (Context)

- `profile apply`는 지원 에이전트 셋의 연결 파일을 늘 만들었다. Antigravity를 쓰지 않는 팀도 `.agents/rules/agctx.md`를 받고, 지우면 다음 `sync`가 다시 만들었다.
- 선택을 명령 옵션으로만 받으면 다른 팀원의 `profile sync`나 예약 봇의 `repos pr`이 뺀 파일을 다시 만든다. 선택은 저장소에 남아야 한다.

## 검토한 대안 (Options)

| 항목 | 대안 | 판단 |
| --- | --- | --- |
| 기록 위치 | `agctx.project.json`의 `agents` | **채택.** 커밋되므로 선택이 저장소 단위의 결정이 되고, 바꾸면 PR diff에 드러난다 |
| | 이 컴퓨터의 저장소 목록(`repos.json`) | 팀원마다 다른 파일이 생긴다 |
| 기록이 없을 때 | 지원 에이전트 전부 | **채택.** 지금까지의 동작과 같고, 지원 에이전트가 늘면 그것도 받는다 |
| `all`의 기록 | 키를 지운다 | **채택.** 위와 같은 뜻을 한 가지 모양으로만 남긴다 |
| | 세 이름을 적는다 | 나중에 늘어난 에이전트를 받지 않는 선택과 구분되지 않는다 |
| 선택을 바꾸는 명령 | `apply`만 | **채택.** `sync`는 기록을 재현하는 명령으로 둔다 |
| | `sync --agent`도 | 고정한 저장소에서 커밋을 유지한 채 선택만 바꿀 수 있지만, 재현 명령과 변경 명령이 섞이고 TUI의 sync 흐름에 질문이 하나 늘어난다 |
| 뺀 에이전트의 파일 | 관리 블록만 지우고, 사람이 쓴 내용이 없으면 파일을 지운다 | **채택** |
| | 그대로 두고 기록에서만 뺀다 | 다음에 다시 고르면 기록 없는 관리 블록을 덮어쓰게 되고, 팀원은 쓰지 않는 파일을 계속 받는다 |

## 결정 (Decision)

1. `profile apply --agent <codex|claude|antigravity|all>`로 연결 파일을 받을 에이전트를 고른다. 쉼표로 여러 개를 준다. `AGENTS.md`는 모든 에이전트가 읽는 정본이라 늘 쓴다.
2. 고른 목록을 `agctx.project.json`의 `agents`에 등록 순서로 기록한다. `all`이면 키를 지운다. `--agent`가 없으면 기록을, 기록도 없으면 전부를 쓴다. `sync`·`repos sync`·`repos pr`·`check`는 기록을 따른다.
3. 기록이 목록이 아니거나, 비었거나, 모르는 이름을 담으면 추측하지 않고 종료 코드 64로 멈춘다.
4. 뺀 에이전트의 파일은 agctx가 관리해 온 경우에만 관리 블록을 지운다. 블록 밖에 사람이 쓴 내용이 없으면 파일과 `.agctx/base/` 사본, 그래서 빈 폴더를 지운다. 계획에는 `remove`로 나온다. 관리 블록을 사람이 고쳤으면 다른 충돌처럼 멈춘다.
5. `explain`은 고르지 않은 에이전트에 `not-selected` 판정을 붙이고 그 에이전트의 `missing`을 종료 코드 4로 세지 않는다. `verify`는 `--agent`로 이름을 대지 않으면 고르지 않은 에이전트를 확인하지 않고 `not-selected`로 보고한다. probe는 에이전트 사용량을 쓰기 때문이다.
6. TUI의 적용 흐름은 기록한 선택을 미리 체크한 에이전트 목록을 보여 준다.

## 결과 및 영향 (Consequences)

- 한 에이전트만 쓰는 팀은 쓰지 않는 파일을 커밋하지 않아도 된다.
- 고르지 않은 에이전트를 쓰는 팀원은 `explain`에서 `not-selected`를 보고, 필요하면 `apply --agent`로 선택을 더하는 PR을 연다.
- 고정한 저장소에서 선택만 바꾸려면 `apply --pin`으로 지금 프로필 커밋에 다시 고정해야 한다. 커밋을 유지한 채 선택만 바꾸는 방법은 없다.
- 대상 종류(규칙·MCP 등) 고르기는 규칙 밖의 대상이 처음 구현될 때 같은 방식으로 더한다.
