# 0045. 명령 출력을 싣는 문서 예시는 메시지 카탈로그를 핀하지 않고 실제 실행과 대조한다

* **상태:** 채택됨 (Accepted)
* **일자:** 2026-09-22
* **결정자:** 제품 소유자
* **근거:** 외부 근거 없음: 이 저장소의 문서 게이트 기록에서 잰 값으로 정한 결정이다. 측정은 [문서 소스 해시 게이트의 핀 범위와 승인 단위](../discussion/repository/topics/doc-gate-pin-scope.md#구현-기록-실행-대조와-해시-줄-제외-2026-09-22)에 있다.
* **관련:** [ADR 0032](0032-cite-code-by-name.md)·[ADR 0033](0033-fingerprint-cited-code.md)(코드를 이름으로 가리키고 지문을 둠). 2026-09-19 제품 소유자 결정의 구현 순서 (1)을 구현한다.

## 배경 (Context)

- 가이드와 개념 문서 12곳이 CLI 출력 몇 줄 때문에 메시지 카탈로그 `src/i18n/messages-en.ts` 전체를 핀했다. 문구를 하나 더하기만 해도 13개 문서가 실패했다.
- #73(6a121eb) 이후 커밋 15개에서 지문만 다시 기록한 (커밋, 문서) 142건 가운데 60건이 카탈로그를 핀한 문서가 카탈로그를 바꾼 커밋에서 걸린 경우였다. 해시 게이트는 그 문서의 예시가 여전히 맞는지는 확인하지 못한다.
- 빠른 시작은 이미 `evals/doc-examples.test.ts`가 예시를 실행해 대조한다. 이 방식은 문구가 달라진 바로 그 예시만 실패한다.

## 검토한 대안 (Options)

| 대안 | 판단 |
| --- | --- |
| 예시 블록에 고정물 이름을 붙이고 평가가 실행해 대조한다 | **채택.** 출력이 바뀐 예시만 실패하고, 문서의 예시가 실제로 맞는지까지 확인한다 |
| 메시지 키를 이름으로 인용하고 지문을 둔다 | 인용 문법이 식별자만 받으므로 문법을 넓혀야 하고, 문구가 맞는지가 아니라 바뀌었는지만 알린다 |
| 카탈로그 핀을 그대로 둔다 | 관련 없는 문구가 바뀔 때마다 헛걸려, 문서를 다시 읽지 않고 지문만 기록하게 만든다 |

## 결정 (Decision)

1. `$` 명령과 그 출력을 싣는 예시는 코드 블록 바로 앞에 `<!-- agctx-example: <고정물 이름> -->`를 둔다. `evals/doc-scenarios.test.ts`의 고정물이 문서의 상태를 만들고 명령을 실행해 출력과 비교한다.
2. 비교는 임시 경로를 문서 경로로 바꾸고, 문서의 커밋 해시 자리에는 실제의 어떤 7자리 16진수든 오되 같은 해시끼리의 대응을 확인하며, `…`는 줄 전체나 줄 끝에서 생략으로만 인정한다.
3. 실행과 대조하는 절은 출력 문구 때문에 메시지 카탈로그를 핀하지 않는다. 화면과 오류 문구를 여럿 인용하는 TUI 가이드와 문제 해결 문서는 카탈로그 파일을 핀하고, CLI Reference와 현재 구조 문서는 `src/i18n` 폴더 핀으로 덮는다.
4. 핀한 문서의 해시 줄은 절마다 모두 해싱에서 뺀다. 절이 여럿인 문서를 핀한 쪽이 지문 줄만 바뀌어 실패하지 않게 한다.

## 결과 및 영향 (Consequences)

- 메시지 카탈로그 파일이나 그 폴더를 핀한 문서는 13개에서 4개가 됐다. 한 소스가 바뀔 때 실패하는 문서 수의 최댓값은 13에서 11이다(중앙값 3, 상위 10% 6은 그대로). README가 `src/profile/setup.ts`를 새로 핀해 그 파일이 바뀔 때 실패하는 문서는 7개에서 9개가 됐다.
- 예시를 실제 출력과 맞추다가 `update-policies.md`의 `profile sync` 예시가 `--yes` 없이 적용 결과를 보여 주는 것을 찾아 고쳤다.
- 새 예시가 새 상태를 요구하면 고정물을 더해야 한다. 고정물은 문서가 글로 설명한 단계(규칙 파일 고치기 등)를 코드로 되풀이한다.
- 해시 줄만 바뀐 문서를 CI에서 경고로 둘지 실패로 둘지는 여전히 정하지 않았다.
