# Agentic 개발 환경 설계 · 범용 설계

2026-09-12 · 설계/구현 프롬프트 패키지 · 런타임 구축 전

## 핵심 판단

첨부 대화의 6~7번은 좋은 출발점이다. 다만 `범용 개선`은 독립된 실행 계층이 아니라 **출처·권리 확인 후 Core에 반영하는 변경 절차**로 바꾸는 것이 명확하다. 실행 중 생긴 회사 프로젝트의 대화, 로그, 화면, fixture, 평가 데이터도 프로젝트 경계 안에 보관해야 한다.

| 분리 대상 | 저장 위치 | 원칙 |
|---|---|---|
| 범용 Core | 별도 개인/권리자 저장소 | 승인된 범용 코드·템플릿·합성 평가만 |
| 프로젝트 Adapter | 프로젝트 저장소 `.agentic/` | 도메인, 명령, 외부 연동 계약, 배포 절차, 프로젝트 정책 |
| 실행 기록 | 프로젝트 전용 비공개 저장소/디렉터리 | 작업·검증·브라우저·대화 기록, 접근/보존 정책 적용 |
| Core 개선 후보 | 우선 프로젝트 안 | 반출·재사용 권리가 확인된 변경만 별도 Core PR로 |

저장소 분리는 출처와 접근권한을 설명하는 기술적 수단이다. 소유권을 확정하지는 않는다. 기존 자산 목록, 사용 허락, 개선물 처리, 계약 종료 후 사용 조건을 별도로 합의할 수 있게 기록 양식까지 설계했다. 법률적 소유권 판정은 이 패키지의 범위가 아니다.

## 구축 순서

| 단계 | 결과 | 도입 시점 |
|---|---|---|
| 0~2 | 현황·경계 기록, 짧은 지침, 로컬 검증 환경 | 가장 먼저 |
| 3~6 | 최소 Core, 런타임 연결, 격리, 재개·증거 검증 | 단일 에이전트 운영 |
| 7 | 역할별 worktree와 독립 리뷰 | 단일 루프 안정화 후 |
| 8~9 | CI·평가·릴리스/인수인계 리허설 | 운영 기준 확보 |
| 10 | 실제 제한된 작업으로 종단 검증 | 구축 완료 판정 |

처음부터 벡터 DB, 상시 에이전트 팀, 자체 모델 실행기, 중앙 SaaS 대시보드는 만들지 않는다. 지침·프로젝트 명령·검증 루프를 먼저 작동시킨 뒤 관측된 병목에 따라 추가한다. [근거](03-sources.md)

## 적용 전 프로젝트에서 확인할 항목

- 현재 HEAD와 사용자 변경을 확인하고, 사실·과거 기록·계획을 구분한다.
- 제품의 구조·언어·런타임·의존성·배포 경로를 확인한다.
- 타입검사·빌드·lint가 포함하는 파일과 제외하는 파일을 기록한다.
- 테스트 발견 수를 확인하고, 테스트 0개를 유효한 성공으로 취급하지 않는다.
- 지침·인수인계·디자인 사본 사이의 충돌을 확인하고 정본을 정한다.
- 디자인 프로토타입과 실제 제품/외부 연동 검사를 구분한다.

이번 산출물은 설계와 실행 프롬프트다. 전역 설정 변경, Harness 설치, 원격 저장소 생성, CI 활성화, 배포는 실행하지 않았다.
