# agctx를 쓰는 이유와 책임 경계

AI 코딩 에이전트에게 TDD·검증·보안 같은 작업 원칙을 지키게 하려면 에이전트가 읽는 지침 파일에 적어야 한다. 저장소와 에이전트가 늘어날 때마다 같은 원칙을 다시 옮겨 적으면 저장소 사이에 규칙이 어긋나고, 팀 규칙이 바뀌어도 어느 저장소가 뒤처졌는지 알기 어렵다. agctx는 공통 지침을 프로필로 한 곳에 두고, 저장소마다 고른 프로필을 적용·동기화하며, 그 지침이 에이전트에 닿는지 확인한다.

## agctx가 하는 일과 하지 않는 일

| agctx가 한다 | agctx가 하지 않는다 |
| --- | --- |
| 프로필 만들기·설정, Git 원격으로 공유 | 모델 호출, 인증, 에이전트 세션 실행 |
| 프로젝트에 적용·동기화하고 적용한 버전 기록 | 코드베이스를 분석해 프로젝트 지침 작성 |
| 여러 저장소를 한 번에 확인·동기화하고 PR 열기 | Git 호스트의 권한·리뷰·병합 |
| 에이전트별 지침 파일 생성과 전달 확인 | 에이전트가 지침을 지키는지 강제 |

에이전트를 실행하는 경우는 사용자가 `verify --probe`로 요청할 때 한 번뿐이다. 코드베이스 분석을 하지 않는 이유는 [ADR 0006](../adr/0006-no-codebase-analysis-guidance.md)에, 목적과 경계의 정본은 [제품 방향](../contributing/product-direction.md)에 있다.

## 명령의 소유권

| 주체          | 책임                                                                         |
| ------------- | ---------------------------------------------------------------------------- |
| 사용자        | 프로필 선택·설정 승인, 적용 대상과 변경 diff 검토, 프로젝트 도메인 지침 관리 |
| agctx       | 프로필·지침 파일 생성, 선택된 프로필의 동기화, 포인터 산출물 제공, 적용 버전 기록·검사, 여러 저장소 동기화·PR 브랜치 push, 에이전트별 지침 전달 판정·확인 |
| AI 에이전트   | 지침을 읽고 프로젝트 코드·테스트를 변경하며 결과를 보고. 스킬로 agctx를 부를 때는 쓰기 명령 전에 사용자 승인을 받음 |
| 대상 프로젝트 | 비즈니스 코드·데이터·도메인 지침·검증 명령 보유                              |
| Git 호스트    | 프로필 원격 저장소의 권한·리뷰·변경 이력                                     |
| CI            | `agctx check`로 저장소가 기록한 프로필 버전과 맞는지 확인                    |

프로필의 공통 지침과 프로젝트의 도메인 지침은 소유자가 다르다. 적용한 프로젝트 `AGENTS.md`에는 둘이 함께 들어가지만, 프로젝트 지침이 프로필로 거꾸로 기록되지는 않는다.
