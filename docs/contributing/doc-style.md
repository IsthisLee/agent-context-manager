# 문서 작성 형식

이 문서는 `docs/`의 문서를 쓸 때 **무엇을 그림·예시로 보여 주고 어떤 형식을 고를지**의 정본이다. 어떤 내용을 어느 문서에 둘지는 루트 [`AGENTS.md`](../../AGENTS.md)의 문서 배치 표가, 게이트 계약은 [문서 게이트](doc-gate.md)가 정본이다.

## 그림과 예시로 먼저 보여 준다

글로만 따라가기 어려운 내용은 그림과 예시로 보여 준다. 그림은 구조와 흐름을, 예시는 사용자가 실제로 입력하고 보게 되는 모습을 보여 준다. 형식은 내용에 맞춰 고른다.

| 보여 줄 내용 | 형식 |
| --- | --- |
| 구성 요소와 책임 경계 | 아키텍처 다이어그램 |
| 명령·동기화 절차 | 플로차트, 시퀀스 다이어그램 |
| 상태 전이 | 상태 다이어그램 |
| 파일·설정·프로필 사이의 관계 | ERD |
| 대안 비교 | 표 |
| 명령 사용법과 결과 | `bash` 코드 블록에 명령과 출력 |
| TUI 흐름 | `text` 코드 블록에 화면(질문·선택지·안내 문구) |
| 생성·관리되는 파일 | `md`·`json` 코드 블록에 파일 발췌(관리 마커 포함) |
| 내부 구현 동작 | 코드 발췌와 `파일:줄` 인용 |

## 형식 규칙

- 기본 형식은 GitHub에서 바로 렌더링되고 diff로 리뷰할 수 있는 Mermaid와 코드 블록이다. archify 같은 도구로 이미지를 만들었다면 그 이미지를 생성한 원본 소스를 같은 변경에 함께 커밋하고, 원본 없이 이미지만 커밋하지 마라.
- 현재 동작을 보여 주는 예시는 실제로 실행한 출력, 실제로 생성된 파일, 현재 코드에서 옮긴다. 출력을 추측해 지어내지 마라. 코드나 출력을 옮긴 문서는 소스 해시 마커로 원본 소스를 핀한다([문서 게이트](doc-gate.md#문서-소스-해시-게이트)).
- 아직 구현되지 않은 명령·화면·파일의 예시는 코드 블록 바로 위에 "제안 예시"라고 밝히고, 현재 동작처럼 쓰지 마라.
- 예시는 핵심을 보여 주는 최소 분량으로 줄이고, 생략한 곳은 `…`로 표시한다.
- 그림과 예시는 본문을 대체하지 않는다. 바로 아래에 보여 주는 대상과 핵심 결론을 한두 문장으로 적고, 논의가 바뀌면 그림·예시·본문을 같은 변경에서 함께 고쳐라.
- 한 문장으로 충분히 설명되는 내용에 장식용 그림이나 예시를 넣지 마라.
