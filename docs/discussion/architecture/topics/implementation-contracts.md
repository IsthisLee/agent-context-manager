# Implementation Documentation Contracts

**상태:** Active process

이 디렉터리는 구현 전에 모든 세부 사항을 확정하는 명세가 아니다. 구현과 eval을 통해 계약을 확정하고, 코드·테스트·문서를 같은 변경에서 함께 갱신한다.

## 상태

각 주제 문서는 제목 바로 아래에 `**상태:** <값>`을 기록한다. 허용 값은 다음과 같다.

* `Proposed`: 논의 중이며 구현 계약으로 확정되지 않음
* `Implementing`: 구현과 eval이 진행 중임
* `Implemented`: 코드와 eval로 동작이 확인됨
* `Superseded`: 새 계약 또는 ADR로 대체됨
* `Active reference`: 비교·근거 문서로 유지됨
* `Active process`: 지속적으로 적용되는 운영 규칙

## 제안 문서 상단 형식

`Proposed` 또는 `Implementing` 상태의 문서는 상태 바로 아래에 **제안 요약**과 **목차**를 둔다. 제안 요약은 항목을 한 표에 나열하지 않고, 다음 세 묶음으로 나눈다.

### 핵심 정보

| 항목 | 기록할 내용 |
| --- | --- |
| 대상 계층 | 사용자, 패키지, 대상 프로젝트, AI 에이전트, 문서·운영 중 영향받는 계층 |
| 제안 목표 | 이 제안이 채택되어 달성하려는 사용자·제품·운영 결과를 한두 문장으로 기술 |
| 제안 이유 | 현재 공백·위험·기회와 지금 논의해야 하는 근거를 한두 문장으로 기술 |
| 결정할 것 | 채택 전 확정해야 할 되돌리기 어려운 정책·계약 3~5개를 짧은 목록으로 기술 |
| 중요도 | Critical·High·Medium·Low와 현재 위험·의존성에 근거한 이유 |

### 제안 관계

| 항목 | 기록할 내용 |
| --- | --- |
| 선행 작업 | 먼저 확정·구현·검증해야 하는 계약 또는 없음 |
| 선행 제안 | 이 문서보다 먼저 검토·채택해야 하는 제안 문서 링크 또는 없음 |
| 후속 제안 | 이 문서의 채택 뒤 구체화·구현할 제안 문서 링크 또는 없음 |
| 연관 제안 | 같은 계층 또는 계약을 공유해 함께 검토해야 하는 제안 문서 링크 |

### 추진 계획

| 항목 | 기록할 내용 |
| --- | --- |
| 후속 작업 | 이 제안이 채택될 때 이어지는 문서·eval·구현·ADR 작업 |
| 권장 다음 작업 | 지금 수행할 가장 작은 검토 또는 검증 행동 |

문서 링크는 이 디렉터리의 상대 경로를 사용하고, 해당 문서가 없으면 `없음`이라고 명시한다. 목차는 문서의 주요 논점과 구현 순서를 보여 준다. 중요도는 확정된 제품 로드맵이나 사용자 약속이 아니라, 논의 우선순위를 판단하기 위한 현재 평가다. `Active reference`·`Active process` 문서에는 이 제안 형식을 강제하지 않는다.

## 구현 기록 형식

```markdown
#### 구현 기록: <기능 또는 변경 이름>

* **상태:** Implemented
* **결정:** 선택한 정책과 계약
* **구현:** 영향받는 파일과 공개 동작
* **검증:** 추가·수정한 eval 및 `npm run check` 결과
* **제약:** 지원하지 않는 경우 또는 후속 작업
* **ADR:** 필요할 때 ADR 링크
```

CLI 명령, JSON schema, artifact 형식, 동기화 계약, 역할 선택 기준, 검증 완료 조건, 런타임 경계, 호환성·마이그레이션·롤백은 기록 대상이다. 단순 내부 리팩터링과 자명한 구현 상세는 기록하지 않는다.

공개 계약이나 운영 정책이 바뀌면 해당 논의 문서와 상태를 같은 변경에서 갱신한다. `Implemented`로 바꾸려면 구현 기록에 코드·eval·`npm run check` 증거를 연결한다. 채택되어 현재 사실이 된 문서는 논의 폴더에 남기지 않고 [`../../../architecture/`](../../../architecture/)로 옮긴다. 여러 프로젝트에 장기 영향을 주거나 되돌리기 어려운 결정은 ADR로 승격한다.
