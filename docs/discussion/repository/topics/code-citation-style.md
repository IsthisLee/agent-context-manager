## 현재 동작

문서는 코드를 세 가지 방식으로 복사한다.

```text
① 줄 번호      `tools/generate-skills.ts:25-28`
② 코드 발췌    문서 안의 ```ts 블록
③ 동작 설명    "요약은 영어 메시지 카탈로그에서 가져온다"
```

[문서 소스 해시 게이트](../../../contributing/doc-gate.md#문서-소스-해시-게이트)가 이 복사본을 지킨다. 인용한 소스가 바뀌면 문서를 다시 읽으라고 알리지만, 다시 읽었는지는 검사하지 못한다.

## 제안 동작

문서의 내용을 종류로 나누고, 종류마다 사람이 다시 읽지 않아도 맞는지 확인되는 방식으로 바꾼다.

| 내용 종류 | 바꾼 뒤 | 맞는지 확인하는 방법 |
| --- | --- | --- |
| 코드 위치 | `tools/generate-skills.ts`의 `SKILLS` | 그 이름이 그 파일에 있는지 `check:docs`가 검사 |
| 코드 발췌 | 없애고 위치만 가리킨다 | 확인할 것이 없다 |
| 코드에서 뽑을 수 있는 사실 | 생성하거나, 생성된 산출물을 가리킨다 | 생성 결과와 대조하는 평가 |
| 동작의 이유 | 코드 옆 주석이나 ADR에 한 번만 적는다 | 코드와 같은 변경에서 고쳐진다 |
| 말로 적은 동작 설명 | 꼭 필요한 것만 남긴다 | 절 단위 해시 게이트 |

22절을 예로 들면 이렇게 바뀐다.

```markdown
## 22. 에이전트용 스킬 생성

스킬 파일의 명령 목록은 사람이 쓰지 않고 명령 등록부에서 생성한다.
어느 명령이 어느 스킬에 들어가는지는 명령의 에이전트 정책이 정한다(ADR 0029).

- 스킬 목록: `tools/generate-skills.ts`의 `SKILLS`
- 표지 사이만 바꾸는 함수: 같은 파일의 `renderSkill`
- 목록이 최신인지 검사: `evals/skills.test.ts`
```

## 결정

2026-09-20, 제품 소유자.

- **복사하지 않고 가리킨다.** `파일:줄` 인용을 `파일`과 `이름`으로 바꾸고, 그 이름이 파일에 있는지 검사한다. 코드 발췌는 없애고, 코드에서 뽑을 수 있는 사실은 생성하거나 생성된 산출물을 가리키고, 이유는 코드 옆 주석과 ADR에 둔다.
- **두 문서의 역할을 나눈다.** `implementation-principles.md`는 npm·Node.js·CLI의 원리를 배우는 학습용 문서로 남기고 설명을 유지하되 인용만 이름으로 바꾼다. `implementation-mechanics.md`는 기능마다 "어느 파일의 어느 이름에 있고 이유는 어느 ADR에 있는지"를 알려 주는 안내도로 줄인다.
- 이 결정은 [핀 범위와 승인 단위](doc-gate-pin-scope.md)의 "`파일:줄` 인용 규칙은 유지한다"를 대체한다.

## 결정·검증 항목

- **인용 형식:** 결정했다. `파일`과 `이름`으로 가리키고 줄 번호를 쓰지 않는다.
- **두 문서의 역할:** 결정했다. 학습용과 안내도로 나눈다.
- **이름이 없는 동작:** 함수 안의 특정 분기처럼 이름으로 가리킬 수 없는 동작을 어떻게 가리킬지는 정하지 않았다. 그 동작을 보장하는 평가의 이름으로 가리키는 방법이 후보다.
