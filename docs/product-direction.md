# Agentic Product Direction

**상태:** 유지되는 제품 방향 (Maintained Direction)  
**최종 확인일:** 2026-09-12

이 문서는 Agentic이 해결하려는 문제, 책임 경계, 장기 구현 방향의 정본이다. README는 처음 사용하는 사람에게 핵심 문제·기능·구조·전제 조건·빠른 시작·검증 범위·동기화 영향을 한 페이지로 소개하고 이 문서를 장기 방향의 기준으로 연결한다. 구현된 현재 사실은 [`architecture/`](architecture/)에서, 세부 제안과 구현 중 계약은 [`discussion/`](discussion/)에서, 되돌리기 어려운 결정은 [`adr/`](adr/)에서 관리한다.

## 목적

Agentic은 여러 AI 코딩 도구가 각 프로젝트를 안전하고 일관되게 개발하도록, 공통 규칙·검증·프로젝트 이해·작업 전략을 제공하는 제어 계층이다.

> Agentic은 AI 에이전트가 계획·구현·검증 루프를 안전하고 일관되게 수행하도록, 공통 규칙과 결정론적 피드백 환경을 제공하는 **에이전틱 개발 기반 패키지**다. 에이전트를 실행·통제하는 런타임이 아니라, 모든 에이전트가 동일하고 안전하게 일하는 프로젝트 환경을 만든다.

## 핵심 방향

1. **공통 규칙의 단일 정본**
   - 대상 프로젝트의 `AGENTS.md`를 공통 규칙의 SSOT로 둔다.
   - Claude Code, Antigravity, Cursor, Copilot용 지침은 이 규칙을 참조하는 동기화 산출물로 관리한다.

2. **프로젝트 네이티브 검증과 증거**
   - Agentic은 프로젝트가 가진 표준 검증 명령(`npm run check`, 테스트 등)을 실행하고, 결과를 기계 판독 가능한 증거로 남긴다.
   - 에이전트의 완료 선언보다 실제 검증 결과를 우선한다.

3. **프로젝트 맥락의 구조화**
   - 장기적으로 `ProjectProfile`은 기술 스택, 제약, 검증 명령, 위험 신호를 구조화한다.
   - 감지하지 못한 정보는 추측하지 않으며, 비밀값·소스 본문·대화 로그를 프로필에 포함하지 않는다.

4. **기본 Solo, 필요한 경우에만 역할 추가**
   - 일반적이고 명확한 작업은 한 에이전트가 계획 → 구현 → 테스트 → 디버깅을 수행한다.
   - 불명확한 범위에는 Planner, 고위험 변경에는 Reviewer·Verifier, 독립적으로 병렬화할 수 있는 큰 작업에만 가상 팀을 선택한다.
   - 역할 간 handoff는 artifact와 완료 기준이 명확할 때만 허용한다.

5. **공식 런타임과의 명확한 경계**
   - Agentic은 `agentic run` 같은 자체 실행기, 벤더 CLI 래퍼, 인증·세션·컨텍스트 관리, stdout/stderr 파서를 만들지 않는다.
   - 모델 호출, CLI 플래그, 인증, 세션, 컨텍스트 압축, 에이전트 간 통신은 공식 도구가 소유한다.

6. **Core와 대상 프로젝트의 자산 분리**
   - Agentic Core는 범용 규칙·정책·동기화·검증 계약을 제공한다.
   - 대상 프로젝트는 비즈니스 코드, 실제 데이터, 도메인 규칙, 제품 테스트를 소유한다.
   - 실행 중 생성되는 artifact는 프로젝트의 `.agentic/`에 두고, 장기 보존할 결정만 문서 또는 ADR로 승격한다.

7. **안전한 콜드 스타트**
   - 테스트 스크립트와 알려진 테스트 파일이 모두 없는 Node 프로젝트에만 내장 테스트 러너와 최소 스모크 테스트를 생성한다.
   - 스모크 테스트는 검증 파이프라인의 시작점일 뿐 제품 테스트를 대체하지 않으며, 기존 테스트 구성은 추측하거나 덮어쓰지 않는다.

## 현재 상태와 다음 단계

| 구분 | 현재 구현 | 다음 방향 |
|---|---|---|
| 규칙·동기화 | `AGENTS.md` SSOT, 도구별 포인터, `init`·`sync` | manifest, `sync --dry-run`, `sync --check` |
| 검증 | `npm test` 실행과 `last-check.json` 기록 | 프로젝트별 검증 계약·신뢰 가능한 테스트 수 정책 |
| 프로젝트 분석 | 기술 제약을 Markdown으로 감지 | 구조화된 `ProjectProfile`, `agentic analyze` |
| 역할 선택 | 단일 에이전트 TDD 지침 | `agentic plan`, 위험도·복잡도 기반 역할 정책 |
| 작업 artifact | 없음 | 필요할 때만 plan·review·verification artifact |
| 콜드 스타트 | 빈 Node 프로젝트에 스모크 테스트 부트스트랩 | 기존 테스트 감지 범위와 진단 경험 고도화 |

## 변경 규칙

이 문서의 목적·책임 경계·기본 작업 모델을 바꾸는 변경은 ADR로 기록하고, README와 관련 아키텍처 문서를 같은 변경에서 정합화한다. 구현 세부 사항이나 아직 검증되지 않은 제안은 이 문서가 아니라 `discussion/`에 기록한다. 모든 문서 변경은 내용의 상태별 정본 위치를 먼저 판정하고, 다른 문서에는 요약과 정본 링크만 두는 규칙을 따른다. 이 규칙의 전체 기준은 루트 `AGENTS.md`의 **문서 체계 및 변경 규칙**에 있다.
