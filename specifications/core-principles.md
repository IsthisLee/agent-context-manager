# Core Principles (핵심 원칙 SSOT)

이 문서는 모든 프로젝트와 모든 AI 에이전트(Codex, Claude Code, Antigravity, Cursor)에 공통으로 적용되는 단일 진실 공급원(Single Source of Truth)이다.

---

## 1. 결정론적 검증 우선 (Deterministic Verification First)

1. **말(텍스트)을 믿지 않고 기계의 결과(Evidence)를 믿는다.**
   * 에이전트는 "테스트를 통과했습니다"라고 말하기 전에 반드시 실제 검증 명령(`npm run check`, `npm test` 등)을 실행해야 한다.
   * 작업 완료 판정은 에이전트의 자기 선언이 아니라, **종료 코드(exitCode 0)와 테스트 통과 개수(passCount > 0)**로만 성립한다.
   * 테스트 실행 결과가 없는 상태에서 완료를 주장하는 것은 환각(Hallucination)으로 간주한다.

2. **테스트 0개는 성공이 아니다.**
   * 테스트가 0개 실행된 채 성공 종료(exitCode 0)된 것은 유효한 검증이 아니다. 최소 1개 이상의 실제 단언(assertion)이 실행되어야 한다.

3. **Red-Green-Refactor TDD 사이클 준수.**
   * **Red (실패 증명):** 버그 수정이나 새 기능 추가 시, 코드 구현에 앞서 **실패하는 테스트를 먼저 작성**하여 결함이나 요구사항을 명확한 실패(Red)로 증명한다.
   * **Green (최소 구현):** 해당 테스트를 통과시키는 데 필요한 **가장 단순하고 최소한의 코드**를 작성하여 성공(Green)시킨다.
   * **Refactor (품질 개선):** 모든 테스트가 통과하는 상태를 엄격히 유지하면서, 중복을 제거하고 가독성을 높이며 설계를 개선한다(Refactor).
   * **규칙:** 프로덕션 코드부터 무턱대고 수정하고 나중에 끼워맞추기식 테스트를 작성하는 행위를 엄격히 금지한다.

---

## 2. 린 컨텍스트 (Lean Context) 원칙

1. **지침 파일의 비대화 금지.**
   * 항상 읽히는 루트 지침(`AGENTS.md`, `CLAUDE.md`, `.gemini/rules/`)은 1~2쪽 이내로 극도로 압축한다.
   * 모든 상세 지식은 온디맨드로 읽는 상세 문서(예: `docs/architecture.md`)로 분리하고, 루트에는 경로 링크만 둔다.

2. **최소 변경 원칙 (Minimal Diff).**
   * 요청받지 않은 무관한 파일의 리팩터링, 전역 포맷팅 변경, 불필요한 주석 삭제를 엄격히 금지한다.
   * 변경된 diff가 작업의 요구사항 범위와 정확히 일치해야 한다.

---

## 3. 자가 회복 (Self-Healing) 및 중단 규약

1. **에러 발생 시 즉각 중단하지 말고 1~2회 자체 수정 시도.**
   * 테스트나 빌드가 실패하면 에러 로그를 읽고 가설을 세워 수정을 시도한다.
2. **동일 에러 3회 반복 시 사용자에게 에스컬레이션.**
   * 같은 에러로 3회 이상 헛돌 경우(무한 루프 방지), 즉시 중단하고 원인과 대안을 사용자에게 보고한다.
