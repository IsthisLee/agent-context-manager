# Security & Boundary Guidelines (보안 및 경계 규칙 SSOT)

이 문서는 공통 하네스(`agentic`)와 개별 프로젝트 간의 관심사 분리 및 보안 규칙을 정의한다.

---

## 1. 영역 분리 및 규칙 승격

1. **프로젝트 고유 코드는 공통 하네스로 복사하지 않는다.**
   * 개별 프로젝트의 도메인 로직, 데이터베이스 덤프, 내부 대화 로그, 스크린샷, 세션 쿠키는 프로젝트 경계 내부에 머물러야 한다.
   * 공통 하네스(`agentic`) 저장소에는 순수 범용 개발 규칙과 도구만 보관한다.

2. **규칙 승격(Promote) 시 순수 기술 패턴으로 추상화.**
   * 프로젝트 작업 중 발견한 유용한 개발 패턴을 `agentic` 공통 규칙으로 승격할 때는:
     * 프로젝트 고유 명칭, 내부 비즈니스 로직, 특정 변수명을 배제한다.
     * 순수한 범용 기술 패턴(예: React 렌더링 최적화 팁, Playwright 안정 대기 전략)으로 추상화하여 반영한다.
   * **서브에이전트(Subagent) 활용 권장:** 서브에이전트를 띄울 때는 순수 기술 요약문만 인수로 전달하여 불필요한 프로젝트 컨텍스트의 전파를 차단한다.

---

## 2. 비밀값 및 환경변수 보호

1. **비밀값의 프롬프트 출력 및 커밋 절대 금지.**
   * `.env`, 비밀 키, API 토큰, JWT, SSH 키, 인증서 파일의 내용을 터미널/대화창에 `cat`하거나 출력하지 않는다.
   * Git 커밋 대상에 `.env`나 인증 자격증명이 포함되어 있는지 커밋 전 반드시 확인한다.

2. **Git 히스토리 보호.**
   * 승인되지 않은 `git push --force`나 `git reset --hard` 등 파괴적 명령은 사용자의 명시적 요청 없이 절대 실행하지 않는다.
   * 메인 브랜치(`main`, `master`)로의 직접 푸시는 사용자가 승인한 경우에만 수행하며, 기본적으로 작업 브랜치를 분기한다.

---

## 3. 최소 권한 및 샌드박스

1. 에이전트가 실행하는 명령은 현재 프로젝트 디렉터리 내부로 한정한다.
2. 부모 디렉터리(`..`)나 시스템 루트(`/etc`, `~/.ssh`)에 대한 무단 탐색이나 쓰기를 금지한다.
