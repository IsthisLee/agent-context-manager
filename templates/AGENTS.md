## 1. 핵심 행동 규약 (필수 준수)

1. **말보다 기계의 검증 증거가 우선이다.**
   - 코드 수정 후에는 반드시 검증 명령을 실행하여 통과 여부를 확인하라.
   - 검증 명령: `{{VERIFY_COMMAND}}`
   - 테스트를 실행하지 않고 "완료했습니다"라고 보고하는 것은 금지된다. 코드 변경은 변경을 검증하는 테스트를 함께 추가하라.
   - 검증 결과는 마지막에 한 줄 대괄호 표기로 간결하게 보고하라. 예: `[ @agentic: npm run check 통과 — 문서 계약 검사와 10개 테스트 통과; 격리된 평가 환경의 경고 2건. ]` 경고·한계가 없으면 마지막 항목은 생략한다.
   - **경고·한계는 먼저 확인한다.** 예상하지 못한 경고, 건너뜀, 불안정성, 검사 범위의 공백을 발견하면 완료 전에 원인과 영향 범위를 직접 조사하고, 작업 범위 안이면 해결한 뒤 다시 검증하라. 해결할 수 없거나 작업 범위를 벗어나면 원인·영향·재현 또는 다음 조치를 마지막 검증 불릿에 적고 사용자에게 설명하라. 이미 문서화되어 재현 가능한 비치명적 경고만 “알려진 경고”로 짧게 보고할 수 있으며, 이를 새 경고를 무시하는 근거로 쓰지 마라.
2. **Red-Green-Refactor TDD 사이클 준수.**
   - **Red:** 버그 수정 및 신규 개발 시, 구현 코드에 앞서 **실패하는 테스트를 먼저 작성**하라.
   - **Green:** 테스트를 통과시키는 최소한의 코드만 작성하라.
   - **Refactor:** 테스트 통과를 유지하며 코드를 깔끔하게 정리하라.
3. **최소 변경 원칙 (Minimal Diff).**
   - 요청받은 기능/버그와 무관한 파일의 리팩터링이나 전역 포맷팅 변경을 하지 마라.
4. **비밀값 보호.**
   - `.env`, 비밀 키, 개인정보를 화면에 출력하거나 커밋하지 마라.
5. **Git 워크플로.**
   - 사용자 승인 없는 `git push --force` 및 파괴적 명령 금지.
